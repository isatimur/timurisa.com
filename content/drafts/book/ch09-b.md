Five checks. One week. No new tools. Chapter 9 closes with a checklist that asks a team to look at how work moves, not how much work gets made. Here is one way to run each item.

## Find the queue and read your rituals

Start with the queue. Find where work piles up waiting on a person. The chapter says that is where scarcity actually moved. It tells you where to invest, so you stop guessing who is slow. Ask each team one question: what is waiting for a human right now? Write down the answers. Review requests, unmade decisions and unchecked drafts are the usual suspects.

Next, check what each ritual rations. A standup that reports how much got produced rations the abundant resource. A standup that surfaces which decisions are unmade rations the scarce one. The chapter says to run the second kind. Change one agenda this week. Replace the output round with a list of decisions waiting on someone.

## Name owners and measure outcomes

Third, name the owner before you widen who can create. The chapter supports broader creation. Support teams, product managers and domain experts should be able to ship meaningful changes. But every path you open needs four answers:

- Who owns the production path?
- Who owns domain correctness?
- Who owns the security boundaries?
- Which workflows stay human-gated?

Decide this before the path opens. Otherwise you discover the gap after something ships.

Fourth, measure outcomes, not artifact volume. The chapter names three numbers: rework rate, the share of generated work that ships unreverted, and time in the review queue. Pull them for one team. A dashboard that only counts pull requests can go green while the real constraint breaks. The chapter cites Nick Arcolano's analysis at Jellyfish, built on some twenty million pull requests, as the failure mode at scale. Output volume rises and the dashboards light up green. Whether the organization can review, integrate and trust that output goes unmeasured until it breaks.

## Check that your voters are independent

The fifth check applies when you use redundancy to judge output. Majority voting and model debate can beat one expensive call. The chapter describes sampling several responses and voting, and having weaker models debate what a stronger model says. But the voters must be genuinely independent. One model sampled five times cancels noise. It does not cancel its shared blind spot. If your review setup samples one model repeatedly, add a voter that can disagree for different reasons.

## Put it on one page

List the five checks on one page and give each to one person. By Friday the page should hold five things:

1. A list of queues.
2. One changed ritual.
3. A named owner for each widened path.
4. Three outcome numbers.
5. A verdict on whether your redundancy is real.

The chapter calls review capacity the control system for organizations that use agents. This page is a small version of it.

A week will not fix everything. It will show where your institution runs on habit instead of written rules. Start with the first gap on the page.
